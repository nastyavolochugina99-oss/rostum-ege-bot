# Публикация бота на сервер: детальный план

Чтобы бот работал постоянно (не только когда открыт терминал у тебя на компьютере), его нужно запускать на сервере в интернете. Ниже — пошаговый план.

---

## Шаг 0. Что выбрать: VPS или «облачный» хостинг

| Вариант | Плюсы | Минусы |
|--------|--------|--------|
| **VPS** (Timeweb, Selectel, Reg.ru, DigitalOcean и т.д.) | Полный контроль, дёшево (от ~200 ₽/мес), бот + база на одном сервере | Нужно один раз настроить по SSH (команды ниже) |
| **PaaS** (Railway, Render, Fly.io) | Почти не нужно настраивать сервер, деплой из Git | Часто платно после trial, меньше контроля |

**Рекомендация:** если есть или планируешь VPS — используй его (план ниже для Ubuntu). Если хочется без возни с сервером — рассмотри Railway или Render (кратко в конце).

---

## Вариант A: публикация на VPS (Ubuntu)

### Что понадобится заранее

- Доступ по **SSH** к серверу (логин + пароль или ключ).
- На сервере — **Ubuntu 20.04 / 22.04** (или другой дистрибутив с Python 3.9+).
- У себя на компьютере: папка бота с кодом и файлом `.env` (токен и `CURATOR_LINK` уже заполнены).

---

### Шаг 1. Подключись к серверу

На своём компьютере открой терминал и выполни (подставь свой логин и адрес сервера):

```bash
ssh имя_пользователя@IP_или_домен_сервера
```

Пример: `ssh root@123.45.67.89` или `ssh ubuntu@myserver.ru`. После ввода пароля ты окажешься в консоли сервера.

---

### Шаг 2. Установи Python 3 и venv (если ещё нет)

На сервере выполни:

```bash
sudo apt update
sudo apt install -y python3 python3-pip python3-venv
python3 --version
```

Должна быть версия 3.9 или выше.

---

### Шаг 3. Создай папку для бота

На сервере:

```bash
mkdir -p ~/rostum-bot
cd ~/rostum-bot
```

Дальше все команды — из этой папки или с указанием пути к ней.

---

### Шаг 4. Перенеси файлы бота на сервер

**Способ 1 — через SCP с твоего компьютера** (в **новом** терминале на **своём** компьютере, не на сервере):

```bash
cd "/Users/anastasia.volochugina/workspace/projects/active/Ростум | ЕГЭ/tutor-booking-bot"

scp -r bot.py storage.py requirements.txt data .env.example "имя_пользователя@IP_сервера:~/rostum-bot/"
```

Папку `data` скопируй целиком (внутри должны быть `slots.json`; `bookings.db` можно не копировать — создастся на сервере).  
**Важно:** файл `.env` с токеном и куратором на сервер лучше передать отдельно (см. ниже), а не через репозиторий.

**Способ 2 — создать файлы вручную на сервере**

На сервере в `~/rostum-bot/` создай те же файлы: скопируй содержимое `bot.py`, `storage.py`, `requirements.txt`, `data/slots.json` из своего проекта. Папку `data` создай командой `mkdir -p ~/rostum-bot/data`.

---

### Шаг 5. Создай на сервере файл .env с секретами

На сервере:

```bash
cd ~/rostum-bot
nano .env
```

Вставь (подставь свой токен и ссылку на куратора):

```
BOT_TOKEN=твой_токен_от_BotFather
CURATOR_LINK=https://t.me/malexsandrovich
```

Сохрани: `Ctrl+O`, Enter, затем `Ctrl+X`.

---

### Шаг 6. Установи зависимости и проверь запуск

На сервере:

```bash
cd ~/rostum-bot
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python bot.py
```

Должно появиться сообщение вроде «Бот запущен» и бот начнёт отвечать в Telegram. Проверь в Telegram `/start`. Остановить тест: `Ctrl+C`.

---

### Шаг 7. Настрой автозапуск через systemd

Чтобы бот работал в фоне и перезапускался после перезагрузки сервера:

1. Выйди из venv: нажми `Ctrl+C`, затем введи `deactivate`.

2. Создай файл сервиса:

```bash
sudo nano /etc/systemd/system/rostum-bot.service
```

3. Вставь (замени `ТВОЙ_ПОЛЬЗОВАТЕЛЬ` на имя пользователя, под которым заходишь по SSH, например `root` или `ubuntu`):

```ini
[Unit]
Description=Ростум ЕГЭ — бот записи на тьюторские сессии
After=network.target

[Service]
Type=simple
User=ТВОЙ_ПОЛЬЗОВАТЕЛЬ
WorkingDirectory=/home/ТВОЙ_ПОЛЬЗОВАТЕЛЬ/rostum-bot
ExecStart=/home/ТВОЙ_ПОЛЬЗОВАТЕЛЬ/rostum-bot/.venv/bin/python bot.py
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

Сохрани: `Ctrl+O`, Enter, `Ctrl+X`.

4. Включи и запусти сервис:

```bash
sudo systemctl daemon-reload
sudo systemctl enable rostum-bot
sudo systemctl start rostum-bot
sudo systemctl status rostum-bot
```

В `status` должно быть `active (running)`. После этого бот опубликован и будет работать постоянно.

---

### Шаг 8. Полезные команды после публикации

| Задача | Команда на сервере |
|--------|---------------------|
| Посмотреть логи бота | `sudo journalctl -u rostum-bot -f` |
| Остановить бота | `sudo systemctl stop rostum-bot` |
| Запустить снова | `sudo systemctl start rostum-bot` |
| Перезапустить после изменения кода | `sudo systemctl restart rostum-bot` |

---

### Обновление бота (новый код или слоты)

1. Перенеси обновлённые файлы на сервер (через SCP или вручную), например снова в `~/rostum-bot/`.
2. Если менял зависимости в `requirements.txt`:  
   `cd ~/rostum-bot && source .venv/bin/activate && pip install -r requirements.txt && deactivate`
3. Перезапусти сервис:  
   `sudo systemctl restart rostum-bot`

Файл `data/bookings.db` на сервере не перезаписывай при обновлении — в нём хранятся записи учеников.

## Вариант B: публикация на Railway / Render (без своего сервера)

1. Зарегистрируйся на [Railway](https://railway.app) или [Render](https://render.com).
2. Создай новый проект и привяжи его к репозиторию с ботом (или загрузи код).
3. В настройках проекта задай **Environment Variables**: `BOT_TOKEN`, `CURATOR_LINK` (значения из твоего `.env`).
4. Укажи команду запуска: `python bot.py` (или через venv, если хостинг так требует).
5. Деплой — бот будет работать пока включён бесплатный/платный план. База `bookings.db` на таких платформах может сбрасываться при пересоздании контейнера — тогда лучше позже перенести бота на VPS с постоянным диском.
